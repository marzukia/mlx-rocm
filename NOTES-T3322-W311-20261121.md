# T3322 (W3.1.1) — the release-path OOB fix + the device-aware scratch location + per-box policy

**Stamp adjudication (cloudy, 2026-11-21). Branch `t3322-w311-device-aware-scratch` (base 5ff9a5a2, PR #47 head), PR #48 stacked on #47. Commit a101c8b9.**

## The two changes (mmq.hip only)

1. **The release-path OOB fix (free-after-last-use).** W3.1 (5ff9a5a2) peeks the wq4 validity
   BEFORE the release trigger fires. On a wrap-trigger dispatch the peek saw a stale
   `wq4_valid=true`; the release freed everything (its drain sync completing every prior
   consumer); `scratch_try` allocated a fresh uninitialized buffer; the repack was SKIPPED
   (stale valid); the GEMM read uninitialized HBM. That is the 9B neon OOB warm-argmax
   248044 (all 4 DEFAULT stamp rounds; the 27B battery was rate-data-only). The fix
   reorders: the release trigger now runs BEFORE the validity peek, so the post-release
   peek sees the emptied cache and the repack runs on the fresh buffer before the GEMM
   consumes it. The free happens after the last use, never before the re-repack.

2. **The device-aware scratch location + per-box default.** The card class via the existing
   `ggml_cuda_info()` shim (the hipGetDeviceProperties family; HIP_VISIBLE_DEVICES-aware):
   - card <20GB (the neon 16GB) → HOST-PINNED scratch (hipHostMalloc/hipFreeHost — not the
     t3116 device-hipFree whole-device sync class) + bounded P1B23 8GB/1GB (the 265055a
     pre-fix shape) + release OFF;
   - card ≥20GB (the 20–32 middle + the helium 32GB) → DEVICE scratch (the t3305 shape) +
     W4 2GB/256MB (the official 293.3/8.15 vehicle) + release OFF.
   - `MLX_ROCM_MMQ_SCRATCH_LOC=host|device` = the A/B override (default = the card class,
     arm-neutral, no env needed).
   - release-ON GATED: OFF by default everywhere; the device class arms on the explicit
     `MLX_ROCM_MMQ_RELEASE_PER_CHUNK=1` only (W3.1's default-ON withdrawn; the use is
     gated on the OOB fix + the both-box token checks). `=0` = the explicit persistent A/B.
   - the W3.1 8GB/1GB and W4 2GB/256MB values stay reachable via the unchanged
     REPACK_MAX_BYTES / XQ81_MAX_BYTES hooks. allocator.cpp untouched (its clear-cache
     hook already checks `mmq_release_per_chunk()`, now no-op by default).

**Proof hooks:** the `[das]` emit under `MLX_MMQ_CFG` (class + caps + release + vram) +
the `T3322-DAS-20261121` / `T3322-OOBFIX-20261121` canaries (both present in the built
lib, plus the T3317-PCREL canary retained).
